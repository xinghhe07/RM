## 0. 铁律（违反过，代价最大）

| 编号 | 铁律 | 踩坑记录 |
|---|---|---|
| **R1** | **验证必须覆盖"真正会执行的那条分支"** | `--log` 会提前 `return 0`，导致"漏 `import mujoco.viewer`"和"`c.gamma` 不存在"两个 bug 都没被测出来。用 `--log` 验证启动路径 = 没验证 |
| **R2** | **任何跨 step 累积/差分状态，必须在 `auto_reset` 里处理** | 已犯 **3 次**：`_lock*/_holder`、`_prev_vp_adv`、`_dist_valid`。第 3 次造成"每局重生白送奖励"，策略学会自杀刷分 |
| **R3** | **"能构建/能导入" ≠ "能运行"** | 模型能 build、模块能 import，但调用路径仍可能崩 |
| **R4** | **奖励权重必须按"整局账本"核算，不能凭感觉** | 配错 3 次：`w_dmg_out` 曾使"打人比占点赚 60%"，策略把伤害刷到 643 而占点率只有 0.002 |
| **R5** | **读指标前先确认它不会被重置** | 训练日志里的 `dmg_out` 会被 `auto_reset` 归零，造成"伤害塌缩"的**假象**，为此白追了好几轮 |
| **R6** | **没有对照基线 = 不知道自己在进步还是在原地打转** | 当前最缺这个。见 §3 |

## 1. 场景 → 必查来源（这是"优先级"的落地形式）

### 场景 A：设计/调整奖励函数
**先查顺序（不要跳步）**：

1. **规则手册本身** —— `RoboMaster 2026 机甲大师高校联盟赛比赛规则手册 V1.2.0.pdf`
   → §3.3.4 / §3.3.5：**胜负判定就是目标函数**。2026 是"扣分制"：双方各 200 起，
   占控制区扣**对方** 1/秒，战亡**自己**扣 20，先归零者负。
   → **伤害本身不给胜利点**。这是最容易被奖励设计带偏的地方。
2. **势函数塑形定理** —— Ng, Harada & Russell 1999（policy invariance）
   → 只有 `F = γΦ(s') − Φ(s)` 不改变最优策略。**禁止加 `.clamp()`**（裁剪会破坏该性质）。
   → 本项目实现：`Φ = −tanh(d/σ)`，`σ = approach_sigma = 3.0`。
   → 自检脚本：`python check_shaping_scale.py`（确认塑形在真实距离范围有效）
3. **Shaping 失败的实证** —— arXiv [1911.01417](https://arxiv.org/abs/1911.01417)《Sibling Rivalry》
   → 原文："PPO with the naive distance-to-goal reward **never succeeds**"
   → 含义：**朴素距离塑形会引入局部最优**，必须用势函数形式。
4. **奖励缩放** —— SB3 `VecNormalize` 源码 + [Andrychowicz et al.](https://arxiv.org/abs/2006.05990)
   → **只缩放、不减均值**；`clip_range_vf` **有害**（SB3 明示"依赖奖励尺度"）。
5. **整局账本自检** —— 项目内跑：
   ```
   python -c "from rm_sentry.rmul_3v3_env import RMUL3v3Config as C; c=C(); ..."
   ```
   核算每项整局总值，确认"占点项主导"（当前 15.5x）。

## 2. 开源生态：明确结论（**别重复搜**）

### 2.1 ⚠️ 最重要的一条：开源哨兵**不用 RL**

已核实的事实（三轮调研）：**所有能找到的哨兵决策仓库都是规则/行为树/状态机**：

| 仓库 | 决策实现 | 证据 |
|---|---|---|
| pb2025_sentry_behavior | 行为树 | 描述原文 "behavior tree for sentry robot decision-making" |
| Artinx_Simulator_for_RM26UC | 行为树 + 决策插件 | `behavior_trees/sentry_btcpp.xml`、`decision_plugins/definitions/` |
| 0xUwUi/wdr26_sentry_auto_decision | C++ 规则 | 语言 C++，无训练代码 |
| RMUC-OfflineRL | **唯一真 RL，但是离线**（IQL/BC/DT） | 描述原文 "offline reinforcement learning" |

**推论（重要）**：
- **"别人的奖励权重"在开源生态里不存在** → 不要再去搜，浪费轮次
- **可借鉴的是"别人的规则逻辑"** → 拿来做基线/对手/降级开关

### 2.3 空白区（三轮检索均未找到 → 是你的机会）

1. "比赛规则 + 裁判系统 + Gym 接口 + 可并行"的 RL 就绪仿真器
2. **"占点扣对方胜利点"机制的 RL 论文或开源** ← 必须自研
3. 混合动作空间（连续+离散多头）RL 策略的现成部署框架
4. 处理"hold position/驻留"奖励的专门论文
5. 任何"哨兵 RL 在正式比赛击败人类队伍"的可验证成绩

> **官方数据集也不能用来监督"占点"**：数据里无占点字段；`目标robot_id` 在
> 120 万条发射 + 25 万条受击里**全为 NULL**；基地被摧毁仅 **1/1226**。
> → 离线数据只能做"守点/控图"塑形，**占点标签必须自设计**。

### 2.4 好哨兵的行为画像（有实测数据，用来定评估指标）

| 指标 | 哨兵 | 步兵 |
|---|---|---|
| 时间集中在 5 个 1m 格子内 | **81.4%** | 40.5% |
| 位置熵 | ≈ 步兵 1/2 | — |
| 场均走过格数 | 25.4 | 73.2 |

→ **"时间集中度 / 位置熵 / 平均驻留时长"应与胜率并列作为评估指标**。
（胜率高但位置熵大 = 乱跑碰运气，不可复现）

## 3. ⏭ 当前最高优先级：补上"对照组基线"

**为什么这是第一优先**：现在有 RL 策略，但**没有规则基线**。
没有基线 → 无法判断 RL 是进步还是原地打转 → 所有调参都失去方向。

**要做什么**：
1. 照 pb2025_sentry_behavior 的逻辑，实现一个**纯规则哨兵**
   （最简版：靠近控制区并在区内驻留 + 可见敌人就开火 + 热量管理）
2. 用**同一评估集**（`EVAL_SEED = 20261007`）测出它的胜率/净胜点/占点率
3. 把它同时作为：**评估基线** + **训练对手**（当前脚本对手太弱）

**验收标准**：拿到规则基线的胜率数字，并确认 RL 策略能否超过它。
