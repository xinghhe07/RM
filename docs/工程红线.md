# 工程红线与兜底设计（最高优先级）

> **本文件优先级高于《工作台.md》的功能进度。**
> 来源：队伍负责人明确要求（2026-10-07）：
>
> > "把工程级，落地，一定不能在比赛时掉，掉了一定要有兜底，
> >  我是一个保底的人，喜欢往坏处想，希望你也是，一定要把基础做好"
>
> **解释**：功能可以少做，可靠性不能妥协。任何"比赛时可能挂"的设计都算未完成。
> 每次设计/编码前先读本文件；每次提交前对照 §7 自检。

---

## 0. 一句话原则

**假设它一定会坏，然后让坏掉的时候也还能打。**

判断标准（不是"能不能跑"，而是）：
1. 它坏了，**有人知道吗**？
2. 它坏了，**机器人还能动吗**？
3. 它坏了，**裁判系统还会判我们输吗**？

---

## 1. 三层兜底架构（必须按这个层次设计）

```
第 3 层  RL 策略（最高上限，最低确定性）      ← 有能力时用
   │  任何异常（NaN / 超时 / 输出越界 / 置信度低 / 心跳丢失）
   ▼
第 2 层  规则基线（确定性，零训练）           ← 兜底层，必须永远可用
   │  自身异常（状态异常 / 依赖缺失）
   ▼
第 1 层  最低安全策略（几行代码，绝不依赖外部） ← 最后防线
   │  仅做"别撞、别烧、别乱射"
   ▼
第 0 层  底盘电控自带保护（不依赖上位机）      ← 物理层，改不了但要知道它在
```

**硬要求**：
- 每层**必须能独立运行**，不依赖上层。
- 切换**必须是自动的**，不能靠人按按钮（比赛中没人反应得过来）。
- 切换的**判定条件必须是最保守的**：**宁可误切，不可漏切**。

---

## 2. 必须监控并触发降级的条件（"坏处想"清单）

| 类别 | 监控项 | 阈值/判据 | 触发动作 |
|---|---|---|---|
| **数值** | 策略输出含 NaN/Inf | 任一维非有限 | 立即切规则层 |
| **数值** | 输出越界 | \|move\|>1.5 或 目标索引非法 | 裁剪；连续 3 次则切层 |
| **时效** | 单次推理耗时 | > 10 ms（当前实测 30.7 µs，留 300x 余量） | 切层并告警 |
| **时效** | 控制周期抖动 | 连续 5 周期超出预算 | 切层 |
| **时效** | 决策线程心跳 | > 200 ms 无更新 | 切层（喂狗机制） |
| **输入** | 观测异常 | 含 NaN/Inf、或全零（可能是传感器掉线） | 保持上一动作；持续 1s 切层 |
| **输入** | 自瞄/裁判系统断连 | 超时 | 切"盲打"规则（不依赖视觉） |
| **状态** | 血量为 0 / 复活中 | 读条状态 | 执行"静止+不射"（省电、避免误判） |
| **状态** | 热量接近上限 | > 阈值 | 强制停火（避免热量锁定） |
| **资源** | 内存/显存增长 | 持续上涨 | 告警 |
| **进程** | 推理进程崩溃 | 退出码非 0 | 由守护进程重启；重启期走规则层 |

**原则：监控项宁多勿少，阈值宁保守勿激进。**

## 3. 比赛现场必须有的"物理兜底"（工程级，不只是代码）

| 项 | 要求 |
|---|---|
| **降级开关** | 遥控器上有一个"立即接管"（R21 要求交调试遥控器，正好用上） |
| **参数回滚** | 能一键加载"上次已验证的配置"，不依赖现场改代码 |
| **模型回滚** | 至少保留 2 个版本的 ONNX，且**做过数值一致性验证** |
| **离线包** | 车端所有依赖（onnxruntime / 模型 / 配置）**离线可装**，不依赖赛场网络 |
| **冷启动检查单** | 上电后按顺序点检（见 §6），5 分钟内能确认全链路 |
| **日志** | 本地落盘（不依赖网络），赛后能复盘 |
| **备用车** | 若有可能，关键比赛带备份整机或备份上位机 |

## 4. 对 RL 线的特别约束（因为他是"保底型"）

1. **RL 永不独占控制权**。RL 只输出**建议**，由一层仲裁决定是否采纳。
2. **RL 的输出必须可验证**：移动指令、目标索引、开火门控都要在合法范围内，且要断言。
3. **RL 必须有"置信度"判据**：例如策略熵过低/过高、value 异常 → 视为不可信 → 切规则。
4. **不训练到最后一刻**。赛前必须冻结一个版本，并留出**回滚窗口**（建议赛前 2 周冻结）。
5. **RL 上线必须渐进**：仿真 → 空场 → 低速 → 半场 → 全场。每一步都有回退点。

---

## 5. 测试要求（"落地"的判据）

任何要上车的东西，必须通过：

| 测试 | 要求 |
|---|---|
| 规则一致性 | `rules_test.py` 全通过（当前 95/95） |
| 训练前体检 | `preflight.py` 全通过（当前 31/31） |
| **数值边界** | 极端输入（全 0 / 全 1 / NaN / 越界）不崩、不产生非法动作 |
| **长时稳定性** | 连续运行 ≥ 1 小时，内存/延迟无劣化趋势 |
| **降级演练** | **人为制造故障**（杀进程 / 断输入 / 注入 NaN），确认自动切层 |
| **断电重启** | 模拟掉电后重启，能自动恢复到可打状态 |
| ONNX 一致性 | PyTorch vs ONNX 最大误差 < 1e-4（当前 1.79e-07） |

**"降级演练"是必做项，不是可选项。** 没演练过的兜底 = 没有兜底。

## 7. 提交前自检（每次改完代码问自己）

1. 改的东西**坏了会怎样**？说出来。
2. 有没有**监控**它坏掉？（没有监控 = 不知道它坏了）
3. 有没有**兜底**？（没有兜底 = 一条路走到黑）
4. 兜底**演练过**吗？
5. 我验证的是**真正会执行的那条路径**吗？（见 AGENTS.md R1）
6. 如果现在比赛，**我敢让它上场吗**？

**第 6 条是最终判据。任何一条答不上来，就不算完成。**

## 8. 已知的可靠性缺口（诚实清单，随进度更新）

| # | 缺口 | 风险 | 状态 |
|---|---|---|---|
| 1 | RL 策略会崩盘（upd 15~20 掉到胜率 0） | 若用最后检查点会直接输 | ⚠️ 未闭环 → **必须加"模型选择"逻辑** |
| 2 | 没有降级/仲裁层 | RL 异常会直接影响底盘 | ⬜ 待实现（本文件 §1） |
| 3 | 没有"模型选择"逻辑 | 保存的是最后一个而非最佳的模型 | ⬜ 待实现 |
| 4 | 没有长时稳定性测试 | 不知连续跑 1 小时是否劣化 | ⬜ 待做 |
| 5 | 没有降级演练脚本 | 无法验证兜底真的能切 | ⬜ 待做 |
| 6 | 规则基线尚未接真实决策接口 | 兜底层目前不可上车 | ⏳ 进行中 |
| 7 | ONNX 未把 argmax/softmax 烤进图 | C++ 侧需自己实现门控，存在口径不一致风险 | ⬜ 待改进（参考卡 §场景 D） |
