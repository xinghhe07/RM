### 0.1 ⚠️ 借鉴阈值前必须核对"场景可比性"（踩坑记录）

**照抄阈值是危险的**，因为阈值总是相对某个场景设定的。

**实例**：照抄 pb2025 的 `hp_min = 200`（占上限 400 的 50%）→ 本项目**开火率掉到
5.7%、占点率腰斩、净胜点 −78 → −103**。

**为什么错**：他们能靠补给**把血回满**，所以 200 是"该收手了"的合理值；
而本项目环境**复活血量只有上限的 20%（= 80）** —— 阈值 200 **比复活血量还高**，
于是复活那一刻就判定"低血量"，策略**永久处于撤退状态、从不开火**。

**规则**：抄任何阈值前，先问三个问题 ——
1. 这个阈值**相对什么**设定的？（上限？复活值？某事件后的初值？）
2. 我们的对应量是**多少**？
3. 阈值和它的大小关系**是否仍然成立**？（如"撤退阈值必须 < 复活血量"）

**落实**：把这类关系写成**代码自检**，让非法配置直接抛错而不是静默退化。
例：`RuleSentry.__init__` 会拒绝 `hp_retreat_ratio` 使阈值 ≥ 复活血量的配置。

**反模式**（已犯）：❌ 自己发明奖励权重，配错 3 次
（若先查 §2.2 的势函数塑形定理 + 账本核算就不会）
❌ 自己发明哨兵规则（若先读 §2.1 的行为树，就知道别人只用"固定点+自转+状态门控"）
❌ 自己发明复活判定（结果连错 3 次）
❌ **照抄阈值不核对场景**（本轮 hp_min=200）

**已解码的 pb2025 RMUL 2025 决策树**（这是本项目目前最重要的借鉴物）：

```xml
<!-- 1) 比赛状态检查：不在比赛 -> 停转 + 不动 -->
<BehaviorTree ID="check_game_status">
  <Fallback>
    <IsGameStatus max_remain_time="420" min_remain_time="0" expected_game_progress="4"/>
    <ForceFailure><Sequence>
        <PublishSpinSpeed spin_speed="0.0"/>
        <PublishTwist v_x="0" v_y="0" v_yaw="0"/>
    </Sequence></ForceFailure>
  </Fallback>
</BehaviorTree>

<!-- 2) 状态门控 + 兜底回原点 -->
<BehaviorTree ID="check_robot_status">
  <Fallback>
    <IsStatusOK ammo_min="0" heat_max="350" hp_min="200"/>
    <ForceFailure><Fallback>
        <IsRfidDetected center_gain_point="false" .../>
        <PubNav2Goal goal="0;0;0"/>          <!-- 兜底：回原点 -->
    </Fallback></ForceFailure>
  </Fallback>
</BehaviorTree>

<!-- 3) 主行为：固定点待着 + 自转扫描 -->
<BehaviorTree ID="rmul_2025">
  <KeepRunningUntilFailure><ForceSuccess><ReactiveSequence>
      <SubTree ID="check_game_start"/>
      <PublishSpinSpeed spin_speed="7.0"/>
      <SubTree ID="check_robot_status"/>
      <PubNav2Goal goal="4.65;-3.5;0"/>      <!-- 固定占位点 -->
  </ReactiveSequence></ForceSuccess></KeepRunningUntilFailure>
</BehaviorTree>
```

**可直接抄的三条**：
| 借用项 | 值 | 说明 |
|---|---|---|
| 血量门控 | `hp_min = 200`（上限 400 的 50%） | 低于一半血量就不做进攻性行为 |
| 热量门控 | `heat_max = 350`（上限 400 的 **87.5%**） | **留余量，不贴上限** |
| 失败兜底 | 状态不 OK 且不在控制区 → **导航回原点** | Fallback 结构 = 兜底范式 |

**注意**：他们的哨兵行为树**只有这些** —— 固定点 + 自转 + 状态保护。
瞄准射击由独立自瞄模块负责。**不要指望从行为树里抄到复杂战术。**

## 3. 明确"没有开源可借鉴"的领域（别重复搜）

以下三轮检索均未找到，**必须自研**：

1. "比赛规则 + 裁判系统 + Gym 接口 + 可并行"的 RL 就绪仿真器
2. **"占点扣对方胜利点"机制的 RL 论文或开源**
3. 混合动作空间（连续+离散多头）RL 策略的现成部署框架
4. 处理"hold position/驻留"奖励的专门论文

**推论**：
- **"别人的奖励权重"不存在** —— 开源哨兵都是规则/行为树，不用 RL
- 可借鉴的是**别人的规则逻辑**，不是别人的奖励函数

## 4. 抓取工具（沙箱禁网时的替代路径）

```bash
# 列出仓库目录下所有文件与 api URL（先抓 tree）
python fetch_github.py plan <owner/repo> <dir> --branch main

# 解码抓回来的 base64 响应并落盘
python fetch_github.py unpack third_party/<repo> --inbox inbox/

# 单个文件解码（web_fetch 的响应存成文件后）
python fetch_github.py --decode-file <响应文件>
```

**沙箱现实**（别重复试）：
- ❌ `git clone` —— 连不上 `github.com:443`
- ⚠️ `raw.githubusercontent.com` —— 时通时断
- ✅ `api.github.com` —— 走 `web_fetch` 可用（返回 base64）
- ⚠️ `bbs.robomaster.com` —— SPA，`web_fetch` 只能取到标题，**正文需人工打开**
