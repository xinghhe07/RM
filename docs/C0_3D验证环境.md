# C0 3D 规则/战术验证环境

> 状态：**M0 审查完成；M1 未批准、未开始**。
> 本文只定义 C0 的范围、契约与验收边界，不含实现代码。
> 配套审计：`docs/C0_规则审计.md`；基线产物：`app/runs/c0/m0_baseline/`。

## 1. 目标

在 MuJoCo 运动学世界里，让现有战术层驱动 1 台哨兵，按 2027 规则跑完整一局，回答：

- 规则与战术逻辑在 3D 场景中是否自洽、可复现？
- Holder / Hunter / Pinner / Quicksilver / Hybrid 五种规则人设的 ΔCD/s、存活、占区、循环
  耗时差异？
- 3D 与 2D 在相同动作/规则下是否一致？差异来自哪里？
- 为 Planner / PPO / 完整 3v3 / ROS2 留出什么接口？

**不是**：完整 3v3、实车成绩、物理保真、视觉/双 Mid-360、ROS2 联调、PPO 训练。

## 2. 范围

| 进 C0 | 不进 C0 |
|---|---|
| 12×8 m 平地、三控制区、己方补给区 | 高地/隧道高程实体、掩体、机器人碰撞 |
| 双进度占点 0~5、控制度 600、战亡 −10 | 金币、发弹兑换、重装 42mm、功率/超级电容 |
| 读条 5/+5、复活 20% 血、无敌 30s、虚弱到补给区 | 敌人复活（C1）、队友（C2）、机间通信 |
| 补给区回血 25%/s、差值 ≥200/≥400 档位 | 感知延迟/漏检/误检（C1） |
| 1 哨兵 + 3 脚本敌人（敌人不复活） | 视觉、双 Mid-360、点云、自瞄 |
| 20 Hz 控制、10 Hz 决策、300 s/6000 tick | ROS2 实车链路、PPO/ONNX |
| 规则人设 + CD 曲线 + 2D/3D 一致性 | 完整 3v3、Planner（A5） |

## 3. 规则口径与日志（强制）

`app/rm_sentry/c0/config.py` 必须提供：

```text
rules_profile: "official" | "2d_compat"
```

- `official`：主口径。按 `docs/C0_规则审计.md` 的官方确认项实现；脚本敌人单独标为非官方对手模型。
- `2d_compat`：只复现旧 2D 环境（敌人伤害 5、无敌方复活、1v3、超时只比控制度、原地复活、矩形
  在场代理卡检测等），只用于一致性对照。
- 每局 `run.json`、`world.jsonl` header、`DecisionLogger` header、`metrics.json` 必须写
  `rules_profile`；`eval_c0` 按 profile 分目录/分表，**禁止跨 profile 合并比较**。

## 4. 坐标（identity mapping）

规则坐标与现有 2D 环境完全一致，只做 mm→m：

```text
x_m = x_spec_mm / 1000
y_m = y_spec_mm / 1000
```

- 不旋转、不翻转；中央 `(6,4)`、红方高地 `(3.5,3.2)`、蓝方高地 `(8.5,4.8)`、己方补给区
  `(1.25,1.0)` 均与 `RMUL3v3Config` 一致。
- C0 哨兵在红方；`P_HIGH_R/P_HIGH_B` 标签与现有战术层一致。
- MuJoCo 世界使用同一 x/y；相机朝向单独配置。若渲染层需要翻转，只影响画面，不得回灌规则状态；
  日志记录 `render_flip`。
- 必须测试：四角/中心、方向向量、点位 ID 绑定、禁止 180° 残留。

## 5. 架构（M1 起实施）

```
TacticalState  ->  decide()/SafetyMonitor/TacticalMachine  ->  TacticalDecision
                                                                   |
                                                          CommandResolver
                                                                   v
                                                          ExecutionCommand
                                                       /                   \
                                              FakeExecutor          MuJoCoKinematicExecutor
                                              （CI/规则）             （3D 验证；后续 ROS2 stub）
                                                       \                   /
                                                        -> ExecutionFeedback / SensorFrame
                                                                   |
                                                                   v
                                                              C0Bridge -> TacticalState
```

- 复用：`tactical/_core.py`、`decision.py`、`machine.py`、`logger.py` 原样。
- 新写：`c0/bridge.py`、`c0/command_resolver.py`、`c0/driver.py`；不复制 2D 的 7 维动作/mask 布局。
- `Executor` Protocol 先实现 `FakeExecutor` 与 `MuJoCoKinematicExecutor`；`Ros2Executor` 只留 stub，
  C0 不 import rclpy。
- 规则权威：C0 新增纯 Python `Referee2027`；2D env 冻结为训练路径和规则 oracle。两套规则必须做
  常量/场景/固定动作回放三层一致性测试；C1 再决定合并或删除重复实现。

## 6. MuJoCo 执行器边界

- 哨兵/敌人用顶层 **mocap body**；Python 侧做全向运动积分，写 `mocap_pos/quat`，`mj_forward`；
  **不调用 `mj_step`**，不写 `data.xpos`（避免 `view_training.py` 的覆盖 bug）。
- LOS 用 `mj_ray`，geom group 只选遮挡物；C0 默认无遮挡（与 2D FOV+射程等价），测试场景临时放墙。
- 全部解析几何，不加载 mesh；MuJoCo 资产路径 ASCII；不设置 `MUJOCO_GL=egl`。
- headless 默认 `mujoco.Renderer`；`--viewer` 可用；渲染失败不得影响 `--no-render` 评测。
- 敌人：镜像现有 `_opponent_policy()`（未控区→中央、已控区→哨兵；0.85 v_max；0.5s 开火；不复活）；
  `2d_compat` 保留“任一敌人开火只聚合一份伤害”的历史行为。

## 7. 资产策略

- **哨兵模型/场地模型**：等实物/官方资料；C0 用解析几何占位，`ph_` 前缀、`[占位]` 注释、日志水印；
  不编造车体尺寸、轮距、云台限位。
- **敌方模型**：可借鉴 GitHub 上较新、较高星的开源车模型，但只接受 Apache-2.0/MIT/BSD 等许可
  干净的资产；AGPL/GPL/无 LICENSE 不复制，只读思路。敌方模型仅作外观，不参与规则/碰撞/性能判定；
  没有合适模型就继续用占位几何。
- 参考方向（M3 再核验）：`rmoss_gz_resources`、`rmu_gazebo_simulator` 等 Apache-2.0 生态；它们
  没有哨兵模型。

## 9. 指标（M2/M4）

- `control_degree_margin`、`delta_cd_per_s`、`time_to_cd_zero_s`
- `survive_duty`、`effective_duty`
- `zone_inside_duty`、`zone_control_duty`、`contested_duty`
- `death_count`、`respawn_ban_s`、`supply_entries`、`supply_loop_s`
- `shots/hits/damage_out/ammo_used/overheat_count`
- `terminal_reason`

所有指标按 `rules_profile`、`seed`、`persona`、`highland_access` 分组；同种子共享敌人初始状态与
随机流；8 个种子只做 C0 筛查，不做显著性宣称。

## 10. 水印与禁止声明

```text
not_full_3v3=true, teammates=0
physics=kinematic_no_dynamics
geometry=flat_proxy_no_highland_no_tunnel
kinematics=v_max_placeholder_3.0
perception=abstract_ray_fov_no_noise
ros2=false, vision=false, ppo=false

```

禁止声明：完整 3v3、实车可迁移、物理保真、2027 官方规则完全一致、C0 胜率是比赛成绩。
