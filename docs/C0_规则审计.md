# C0 规则审计（M0，2026-10-18）

> 范围：RMUL 2027 3v3 哨兵 3D 规则/战术验证环境 C0。
> 目的：把**官方规则 / 现有代码行为 / 实验假设 / 占位参数**分开，防止把 2D 兼容模型当成 2027 官
> 方规则。
> 结论先行：**现有 `rmul_3v3_env.py` 是 2D 兼容模型，不是完全规则忠实的 2027。** C0 必须显式选择
> `rules_profile`，默认主口径为 `official`，`2d_compat` 只用于复现旧 2D 环境。
> 本文件不修改任何受保护代码。

## 0. 依据与优先级

| 类型 | 依据 |
|---|---|
| 官方规则 | `rules/rules_text/rmul2027_v100.txt`（《RoboMaster 2027 机甲大师高校联盟赛比赛规则手册 V1.0.0（20261015）》） |
| 官方场地 | `docs/2027场地规格.md`（官方图纸实测，配置数据；图纸误差 ±10%，<100mm 结构 ±5mm，未注明处“以实际场地为准”） |
| 现有实现 | `app/rm_sentry/rmul_3v3_env.py`、`app/rm_sentry/tactical/` |
| 旧基线 | `app/runs/c0/m0_baseline/`（2026-10-18 实测） |

冲突时：**官方规则 > 文档 > 现有代码行为**。无法确认的条目必须标 `[待核]` 或 `[假设]`，不得
自行补数。

## 1. 规则口径（强制）

C0 配置必须有显式字段：

```text
rules_profile: "official" | "2d_compat"
```

- `official`：C0 的主口径。官方常量与已确认机制按本文件执行；脚本敌人仍是**非官方对手模型**，
  单独标参数。
- `2d_compat`：只用于复现旧 2D 环境、做 2D/3D 一致性对照。它包含敌人伤害 5、敌人不复活、1v3、
  超时只比控制度、原地复活、矩形在场代理卡检测等非官方行为，**不能当作 2027 官方规则**。
- `rules_profile` 必须写入每局 `run.json`、`world.jsonl` header、`DecisionLogger` header 和
  `metrics.json`；`eval_c0` 按 profile 分目录/分表，**禁止跨 profile 合并 CD 曲线或配对统计**。
- 任何报告标题/图例必须带 profile；`official` 的数字也不能外推为完整 3v3 或实车成绩。

## 2. 坐标与阵营（identity mapping）

### 2.1 规则坐标

采用**恒等映射**，只做单位转换：

```text
x_m = x_spec_mm / 1000
y_m = y_spec_mm / 1000
```

不做 180° 旋转、不做 y 翻转。官方坐标系原点为红方启动区角，x 向右、y 向下；C0 直接沿用这组
数值。MuJoCo 世界同样使用这组 x/y（场地平面在 x-y，z 向上）；相机朝向单独配置。

> 原计划的 180° 方案已撤回：它会把红/蓝高地标签互换，并让 C0 哨兵变成官方蓝方，破坏与现有
> `zones_rect`、`P_HIGH_R/P_HIGH_B` 和 2D 基线的对照。

### 2.2 官方矩形 → 现有配置

| 官方元素 | 官方范围（mm） | 恒等映射结果（m） | 现有配置 |
|---|---|---|---|
| 中央控制区 | (4500,2500)-(7500,5500) | center (6.0,4.0)，hw/hh 1.5 | `zones_rect[0]` `Z_CENTER` ✅ |
| 红方高地控制区 | (2900,2600)-(4100,3800) | center (3.5,3.2)，hw/hh 0.6 | `zones_rect[1]` `Z_HIGH_R` ✅ |
| 蓝方高地控制区 | (7900,4200)-(9100,5400) | center (8.5,4.8)，hw/hh 0.6 | `zones_rect[2]` `Z_HIGH_B` ✅ |
| 红方启动/补给区 | (0,0)-(2500,2000) | center (1.25,1.0)，hw/hh (1.25,1.0) | `own_supply_rect` ✅ |
| 蓝方启动/补给区 | (9500,6000)-(12000,8000) | 东北角 | 敌方出生侧 |

### 2.3 阵营/标签/点位契约

- 恒等映射下，C0 哨兵在**红方**出生/补给，与现有 2D 环境的 `own_supply_rect` 一致。
- 高地标签：红方高地 = 西侧 `(3.5,3.2)`，蓝方高地 = 东侧 `(8.5,4.8)`；与 `P_HIGH_R/P_HIGH_B` 一致。
- 方向向量：保持官方 x 右、y 下；任何进入规则/战术层的向量不得翻转。
- 若渲染需要视觉翻转，只允许在渲染层做，并记录 `render_flip`；规则状态、点位 ID、日志坐标不得翻转。
- 测试必须覆盖：四角/中心与 config 逐值一致、往返、x/y 方向、点位 ID 绑定、禁止 180° 残留。

## 4. 现有 2D 代码行为（非官方，必须隔离）

以下行为来自 `app/rm_sentry/rmul_3v3_env.py`，是 C0 的**兼容基线**，不是 2027 官方规则：

| 行为 | 现有实现 | 与官方的差异/说明 |
|---|---|---|
| 对战规模 | 1 哨兵 vs 3 脚本敌人 | 官方 3v3 每方 3 台；无队友、无机间通信约束 |
| 敌人属性 | HP 200、单发 5、0.5 s 冷却 | 官方 17mm 单发 20；敌人是脚本对手，不是官方机器人模型 |
| 敌人复活 | 不复活 | 官方机器人可读条复活；C1 再补 |
| 敌人 AI | 未控区 → 中央；已控区 → 追哨兵；无 FOV/LOS | 非官方；C0 只用于可比性 |
| 敌人伤害聚合 | 任一敌人本 tick 开火 → 只扣一份 5 | 非官方；C1 可切逐敌结算 |
| 超时判定 | 只比较控制度 | 官方还有伤害/剩余血量/平局链 |
| 哨兵复活位置 | 原地复活（不重置位置） | 官方未明确复活位置；标 `[待核]` |
| 控制区激活 | 矩形在场代理 | 官方为场地交互模块卡检测；卡范围未确认，标 `[假设]` |
| 控制区计时 | 连续进度，无卡失效宽限 | 与官方四条动力学一致；卡检测细节未建模 |
| 伤害模型 | 即时命中 + 距离衰减 0.35、射程 8m | 官方有有效检测速度（>12 m/s）、弹道/入射角；C0 未建模 |
| 感知 | FOV 120°、9m、延迟/噪声/漏检 | 建模假设；C0 `official` 也不代表实车感知 |
| 运动学 | `v_max=3.0`、无加速度/碰撞 | 占位；真实参数待机械数单 |
| 高地/隧道/工作台 | 无实体，仅控制区矩形 | 未建模 |
| 经济/重装/队友 | 无 | 未建模 |

### 4.1 已确认的代码细节

- `dmg_base=20`（2027 档案，`rmul_3v3_env.py:266`）的注释仍写 `[待核]`，但官方表 3-8 已确认 20；
  **值正确、注释过时**。M1 可只改注释，需批准。
- `enemy_dmg_per_hit=5`、`enemy_hp=200`、`enemy_fire_interval=0.5`（`:202-215`）是脚本对手参数。
- 2027 控制区/控制度在 `:811-858`；开火/伤害在 `:860-970`；复活/无敌/虚弱/补给在 `:974-1053`；
  终止在 `:1107-1122`。
- 超时只比较控制度：`:1119-1122`；没有官方伤害/剩余血量/平局链。
- 敌人不复活：`:772`、`:923-925`、`:955-961`。
- 复活不重置位置：`:1006-1020`。
- `_zone_presence()` 用矩形包含（`:600-622`），不是卡检测。
- 动作接口遗留：`action_mask()` 列布局（`:719-736`）与 `step()` 读取列（`:861-862`）不一致；
  C0 不复制 7 维动作/mask 布局。
- `tactical/__init__.py` 无条件导入 `adapter`，经其拉起 torch 和 2D 环境（`tactical/__init__.py:17-30`）；
  未来 ROS2 需做 lazy import。
- `view_training.py` 写 `data.xpos` 后再 `mj_forward` 会被覆盖（`sync_scene` / `run_loop`），只能
  当可视化参考，不能作为 C0 执行器。

## 5. 实验假设（必须显式标注）

| 假设 | 当前取值/做法 | 影响 |
|---|---|---|
| 1v3 场景 | 1 哨兵 + 3 脚本敌人 | 不能外推完整 3v3 |
| 脚本敌人 | 沿用 2D `_opponent_policy` 的镜像 | 胜负高度依赖对手模型 |
| 敌人不复活 | C0 固定 | 与官方机制不同；C1 补 |
| 控制区激活 | 矩形在场代理 | 官方卡检测范围未确认 |
| 复活位置 | 原地（可切出生区） | 官方未明确 |
| 高地控制区 | 平地代理，无高程 | 无法回答上高地是否值得 |
| 隧道/工作台 | 不建模 | 无法回答压隧道/通行 |
| 高地/隧道增益 | 不建模 | 不影响 C0 规则主链路 |
| 经济/兑换/重装 | 不建模 | 哨兵本身不能用金币换弹（官方），但重装机制缺失 |
| 伤害/弹道 | 即时命中 + 射程/衰减假设 | 不是官方弹道模型 |
| 感知 | FOV/距离/延迟/噪声假设 | 不是实车感知 |
| 队友/通信 | 无 | C2 再补 |

## 7. 待核实/未建模（不得自行猜测）

1. 控制区/补给区场地交互模块卡的检测范围、死区；C0 用矩形在场代理。
2. 复活位置（出生区 vs 原地）；官方未规定。
3. 高地平台三维形状、坡道位置/坡度、哨兵能否上高地。
4. 隧道净空、通过方式（穿越/跨越）。
5. 17mm 弹丸有效检测速度、弹道、入射角、伤害检测细节（C0 即时命中）。
6. 控制度/占领进度/伤害事件是否在哨兵串口数据中可直读。
7. 赛前角色参数（holder/hunter 等）合法性。
8. 重装/42mm 屏蔽、金币兑换发弹量的完整经济。
9. 完整 3v3 的队友行为、禁机间通信下的局部观测/协同。

## 8. C0 验收口径

- `official` 是主口径；`2d_compat` 只做 2D 对照。
- 任何 CD 曲线/人设结论必须带 `rules_profile`、`seed`、`persona`、`highland_access`、水印。
- C0 不能声称：完整 3v3、实车可迁移、物理保真、官方规则完全一致。
- M1 前置：本审计确认；`rules_profile` 配置与日志传播测试；现有基线不回归；受保护文件零改动。
