## 1. 机械/运动学（占位参考值 —— 实车尺寸待机械组，见 §6）

### 1.1 底盘参数（占位参考值；来源：`Neomelt/rm_sim_26` 的 `mecanum_car/robot.urdf`——**该参考车是麦轮**，全向轮版实车尺寸待机械组）

| 项 | 值 |
|---|---|
| 四轮位置 | `(±0.20, ±0.21, 0)` → **轴距 400 mm，轮距 420 mm** |
| 轮轴方向 | 各轮轴向指向机体中心（**全向轮 4 轮 X 型**：轴向与机体轴成 45°，滚动方向 ⟂ 轴） |
| 装甲板 | 前 `+0.243` / 后 `−0.243` / 左 `+0.184` / 右 `−0.184`，尺寸 **135 × 125 mm** |
| 底盘外缘 | **486 × 368 mm** |
| 云台 yaw | `z = +0.205`，限位 ±180° |
| 云台 pitch | 相对 yaw 偏移 `(0.06, 0, 0.08)`，**绕 −Y**，限位 ±45° |
| 相机安装点 | pitch 上方再前 0.08 m |
| 整机高 | ≈ 385 mm |

⛔ **原实现已于 2026-10-12 废弃、2026-10-15 连同 `_已废弃模型/` 目录整体删除**：
那份模型的**场地与几何参数是凭空编的**（12×8 m、控制区半径 0.8 m、掩体位置无依据），

→ **重建前提**：拿到真实车体尺寸（轮径/轴距/轮距/云台限位）后重做，见 §6 待确认清单。
→ **场地部分已有真实数据**：`2027场地规格.md`（官方图纸，2026-10-15 提取）。

### 1.2 全向轮运动学（4 轮 X 型；要电控/算法一起确认）

```
4 轮全向轮 X 型：轮位 (±Lx, ±Ly)，各轮轴向指向机体中心 ⇒ 滚动方向 ⟂ 轴、对角对平行
（FL/RR 同滚动线、FR/RL 同滚动线）。机体系 x 前、y 左，取
d_FL=(1,-1)/√2、d_FR=(1,1)/√2、d_RL=(-1,-1)/√2、d_RR=(-1,1)/√2，
通用式 w_i·r = d_i·v + (p_i×d_i)_z·ω 展开：

w_FL = ( vx - vy - (Lx+Ly)·ω) / (√2·r)
w_FR = ( vx + vy + (Lx+Ly)·ω) / (√2·r)
w_RL = (-vx - vy + (Lx+Ly)·ω) / (√2·r)
w_RR = (-vx + vy - (Lx+Ly)·ω) / (√2·r)
其中 Lx = 0.20 m, Ly = 0.21 m, r = 0.065 m（§1.1 参考值）
```

⚠️ **与麦轮同构**：4 轮全向 X 型与麦轮解算**同形**（对角对滚动方向平行）——
差异只有 ① 每轮正方向符号（随装配而定；后轮与前轮的极性约定相反）② 整体 1/√2 系数。
**符号必须装车标定**（电机正方向 + 轮子滚向定义），本文档按上述约定书写。

**借鉴**：`rm-controls/rm_control`（BSD-3，2026 仍活跃）已有现成麦轮底盘控制器 —— 解算与全向 X 型同构，**大概率可小改复用**（符号标定 + √2 系数；是否有硬编码麦轮约定以读源码为准），**别整套自己重写**。

⚠️ **待你们确认**：轮半径 65 mm 是估值（URDF 只给 mesh）。**让机械组量一下实车轮径**，否则里程计会系统性偏差。（全向轮版同样成立，且需再确认轮位。）

## 2. 感知：前后双 Mid-360（你们的配置，有独特优势）

### 2.1 为什么双 Mid-360 是好事

| 能力 | 单 Mid-360 | **前后双 Mid-360** |
|---|---|---|
| 水平 FOV | 360°（但**有近场盲区**，被自身结构遮挡） | **真 360°，互补遮挡** |
| 盲区 | 云台/弹仓遮挡处有洞 | **一个的盲区被另一个覆盖** |
| 定位鲁棒性 | 单雷达退化（长廊/空旷）易丢 | **冗余，退化场景可互救** |
| 对称性 | 前后不对称 → 需额外配平 | **前后对称，旋转不变性好** |

**这是比多数开源哨兵方案更强的配置** —— 我查到的哨兵导航开源（`pb2025_sentry_nav`、`HWSentryNav26`、`COD_NAV`）**基本都是单 Mid-360**。

### 2.2 定位方案

| 方案 | 出处 | 说明 |
|---|---|---|
| **Point-LIO** | `pb2025_sentry_nav` 用的 | 高频、抗剧烈运动；适合哨兵小陀螺自转 |
| **FAST-LIO2** | `HWSentryNav26`、`ZhuoruiYUN/Sentry-Navigation` 用 | 成熟、生态大 |
| **双雷达融合** | ⚠️ 我查到的开源**都是单雷达**，双雷达融合需自研 | 见下方建议 |

**双 Mid-360 的工程建议（⚠️ 部分无开源依据）**：
1. **两路独立跑 LIO** → 各自出位姿 → 用「位姿一致性检查」互为健康监控
   （一路漂移/丢跟踪时，另一路接管）
2. 或**外参标定后合并点云** → 单路 LIO 输入双倍点
3. **Mid-360 是非重复扫描**，两台的扫描图案不同 → 合并后点云更均匀，对建图有利

**必须做的标定**：两台雷达的**外参**（相对位姿）。仓库里 `pb2025_sentry_nav` 有标定工具可参考。

### 2.3 感知（视觉）

**已有**：`RMUL-3v3-视觉上位机作战手册.md`（你自己写的，90 天路线）

**关键约束**（RMUL 规则）：**哨兵禁止机间通信** → **拿不到敌人坐标、没有雷达** → **必须纯机载感知**。

**借鉴**：
- 自瞄：`rmoss_contrib`（Apache-2.0，含自动瞄准模块）
- 视觉库：`cv-rmvl/rmvl`（Apache-2.0，110★，RM 社区通用视觉库）

## 3. 决策架构（核心，三层可降级）

### 3.1 架构图（借鉴 `pb2025_sentry_behavior` 的行为树结构）

```
上层战术决策（去哪 / 占不占点 / 打谁）
   ├── 档 1：RL 策略（上限最高）      ← 自研，需训练
   ├── 档 2：行为树（确定性，可解释）  ← 抄 pb2025_sentry_behavior
   └── 档 3：最低安全策略（几行代码）  ← 只做"别撞、别烧、别乱射"
                ↓
       仲裁层（自动降级，见 工程红线.md）
                ↓
中层：Nav2 导航（把"去哪"变成路径）
                ↓
底层：全向轮底盘控制（rm_control 同构复用）+ 云台/发射控制
```

### 3.2 档 2：行为树 —— **直接抄 pb2025_sentry_behavior**

**这是本方案最值得抄的东西**（Apache-2.0，可商用）。我已解码它的 `behavior_trees/rmul_2025.xml`：

```xml
<!-- 他们的哨兵实际只做四件事 -->
1. 比赛状态检查  → 不在比赛就停下
2. PublishSpinSpeed spin_speed="7.0"   ← 雷达自转 7 rad/s
3. IsStatusOK ammo_min=0 heat_max=350 hp_min=200   ← 状态门控
4. PubNav2Goal goal="4.65;-3.5;0"      ← 去一个固定点待着
```

**结构范式（照抄）**：`Fallback` + `ReactiveSequence`，**状态检查在前、动作在后**，
失败走安全动作（回原点 `0;0;0`）。

⚠️ **但有一条不能照抄**（我已踩坑）：他们的 `hp_min=200` 是相对"能回满血"的场景；
**若你的复活血量只有 20%（80），阈值必须 < 80**，否则会"复活即撤退、永久不开火"。
→ **借鉴阈值前必须核对场景可比性**（见 `开源借鉴.md` §0.1）。

### 3.3 档 1：RL 策略 —— 自研（社区没有）

**事实**：我查了三轮，**没有任何开源项目做 3v3 哨兵 RL**。
- 开源哨兵**全是行为树/状态机**（`pb2025_sentry_behavior`、`Artinx`、`wdr26_sentry_auto_decision`）
- 唯一真 RL 是 `RMUC-OfflineRL`，但**离线、RMUC 7v7、无闭环**

**所以档 1 要自研**，但要**复用 `practice/rc_mjlab` 的工程范式**（见 §4）。

## 4. 训练方案：以 `practice/rc_mjlab` 为模板

### 4.1 可以照搬的（`zeitvex/RC_WheelLeg`，MIT，141★）

| 项 | 他们的值 | 我们怎么用 |
|---|---|---|
| **并行环境** | **2048** | 照搬（你 8 GB 显存可降到 512~1024，见我给的启动器） |
| **物理/策略频率** | 200 Hz 物理 / **50 Hz 策略** | 照搬（战术层可更慢，10~20 Hz 够） |
| **课程学习** | 8 类地形按训练步数释放 | **改成**：对手强度/场地复杂度按步数释放 |
| **域随机化** | 质心偏移 ±0.05 m、摩擦 [0.3,1.0]、刚度/阻尼 [0.9,1.1]、质量 [−1,3] kg、动作延迟 0~2 步 | **照搬这套清单**（战术层也要随机化：感知漏检、通信延迟） |
| **非对称 actor-critic** | actor 53 维 / **critic 333 维**（多 `height_scan(273)` 特权信息） | **照搬这个范式**：critic 看全局（敌人真实位置），actor 只看机载 |
| **观察归一化** | `obs_normalizer: Identity()` | 注意：他们**没做**归一化 |
| **网络** | MLP 53→512→256→128→16 | 规模可照搬 |
| **部署** | `model_6800.onnx` → ROS2/C++ | 照搬 ONNX 契约 |

### 4.2 必须自己做的（轮腿 → 全向轮）

| 项 | 轮腿（他们） | **我们（全向轮）** |
|---|---|---|
| 动作空间 | 16：12 腿关节位置 + 4 轮速 | **3**：`vx, vy, ω`（全向轮解算交给底层） |
| 观测 | 53：IMU + 关节 + 指令 | **本体 + 战场态势**（敌人、控制区、血量热量） |
| 奖励 | 速度跟踪 | **比赛胜负**（2026 胜利点） |
| 地形 | 8 类越野地形 | **平地 + 高地/隧道**（2027 场地，见 `2027场地规格.md`） |

**关键简化**：全向底盘**不需要学"怎么走"** —— 解算（§1.2）直接给 `vx,vy,ω` 就能动。
所以**RL 只学战术决策，不学运动控制**。这比轮腿方案**简单得多**，也第一年更可行。

### 4.3 训练环境（自研，已有基础）

`C:\RM\rm_sentry\` 已有：
- `rmul_3v3_env.py` — 双赛季向量化环境（`rules_test` **95/95**）
- `train_ppo.py` — PPO（混合动作 + 掩码 + per-minibatch 归一化 + 按-epoch KL 早停）
- `export_onnx.py` — ONNX 导出（**30.7 µs**，误差 1.79e-07）

⚠️ **但它有两个已知问题**（见 `工作台.md`）：
1. **场地参数是我编的**（`12×8 m`、控制区半径 `0.8 m`、掩体位置无依据）→ **必须按真实场地图改**
2. RL 策略**会崩盘**（占点率长期 ~0.002）→ 未闭环

### 4.4 评估指标（借鉴 `参考卡.md` §2.4）

| 指标 | 哨兵基准（来自 RMUC 数据集分析） |
|---|---|
| **时间集中在 5 个 1m 格子内** | **81.4%**（步兵 40.5%） |
| 位置熵 | ≈ 步兵 1/2 |

## 8. 建议的实施顺序（"稳优先"）

```
第 1 步  抄 pb2025_sentry_behavior 的行为树 → 让哨兵能上场（保底）
第 2 步  拿到真实场地图纸 → 改我的环境参数 → 重新基准化
第 3 步  用 rm_control 接通全向轮底盘（解算同构；符号标定后复用）
第 4 步  双 Mid-360 标定 + 定位验证（空场跑）
第 5 步  以行为树为对手/门槛，训 RL（借鉴 rc_mjlab 框架）
第 6 步  RL 通过验收门槛后才替换行为树（工程目标.md §6）
```

**核心原则**：**第 1 步就保证"能打"，后面都是加分。**
