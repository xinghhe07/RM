### ▶ 2026-10-13 新增：战术层骨架（几何无关）

**背景**：队伍负责人定下保底路线 —— **战术点图 + 决策树 + 状态机**，
先有一套不依赖 RL 也能独立运行的哨兵策略，再让 RL 优化战术选择。
本轮把它落成了代码骨架，**坐标全部是配置数据**（守住交接文档 §9 红线）。

**结构**（`rm_sentry/tactical/`）：

| 模块 | 职责 | 关键契约 |
|---|---|---|
| `_core.py` | 点图 + 状态快照 + 动作集 | 点 = **命名点 + 区域绑定**；控制类点位必须绑区域（构造时强制） |
| `decision.py` | 优先级栈 + 安全监督 + 选点评分 | 安全 → 复活/保护/虚弱 → 导航有效 → 当前任务保持 → 重新选点 |
| `machine.py` | 执行状态机 | IDLE/MOVING/EXECUTING/RETREATING/RECOVERING，每个状态有超时与失败后动作 |

**决策优先级的落地**：安全层任何非 NORMAL 状态 → 一律 `SAFE_MODE`（停）；
复活/保护期 → 原地不动；虚弱或血量 < 30% → 撤离到**可达**安全点（无安全点则原地保守）；
导航连续失败 → RECOVER（带 2 s 最短保持，防"卡住→恢复→立刻重发"抖振）。

**动作集 = 规则层与 RL 层共用**：`HOLD_CURRENT_ZONE / CAPTURE_POINT / DEFEND_POINT /
PATROL_POINT / RETREAT / RECOVER / SUPPORT_TEAMMATE / SAFE_MODE`。
RL 的离散动作就是"需要目标的动作 × 点 ID"，与环境的 `action_mask` 机制天然对齐。

**验证**：`python test_tactical.py` —— **39 项全通过**，覆盖
定位丢失 / 点位不可达 / 任务超时 / 控制区易手 / 复活序列 / 信息过期 / 目标防抖
/ 点到区域绑定 / RL 动作接口稳定性 / 与环境规则常量一致性。
全部用合成点图，**不依赖任何真实坐标** ⇒ 真实场地图到位后直接复用。

**环境适配器（`tactical/adapter.py`，同日完成）**：

```
BatchedRMUL3v3 张量 --to_tactical_state()--> TacticalState --decide()--> TacticalDecision
                                                                              |
                                              decision_to_env_action()  <-----+
                                                       |
                                                  [vx, vy, target, fire]
```

单向依赖：战术层不认识张量列索引，环境不认识战术动作枚举，两端只认中间契约。
**这就是"真车可迁移"的落点** —— 真车上换成 ROS 话题数据源即可，战术层一行不改。

已验证（`test_tactical_adapter.py` 28/28）：
- 归属判定**现算位置**，与 `env._holder` 解耦（防止"上一步的副产物"污染决策）
- 信息孤岛：不可见敌人**不得**进快照（哨兵禁止机间通信）
- 所有动作尊重掩码；安全层压制时移动/开火恒为 0
- `reset()` 后输出与全新驱动器**逐位一致**（跨步状态无残留，R2）
- 连续跑完整局 6000 步不崩；决策 10 Hz / 环境 20 Hz 对齐（`decide_every=2`）

⚠️ **已知性能差**：逐环境 Python 决策 ≈ **1k 环境步/秒**，是向量环境（511k）的 1/500。
   跑规则基线和冒烟可以，**当 RL 训练对手不够用** —— 需要时再向量化，
   但**不得**为了提速破坏"战术层不知道批量维度"这层隔离。

**下一步（本层未做的）**：
1. 权重标定：`ScoringWeights` 全是 [默认] 待标定值，真图到位后用固定种子评估调
2. 决策日志落盘（`TaskTransition.reason` 已带完整评分分量，接文件即可）
3. 真图到位后替换：点图坐标、`center_r`、以及"路径代价用直线距离代理"这一处

## 五、⚠️ 本轮发现的环境 bug（已修，必须记住）

### 5.1 复活逻辑：**连续错了三次**

每一次的后果都是**哨兵永久死亡**或**每步白送一次复活**，
让所有长于 ~13 秒的评测**全部失真**：

| 错法 | 为什么错 |
|---|---|
| 先递减 `DEAD` 并 `clamp(0)`，再判断 `DEAD > 0` | 归零后永假 → **永不复活** |
| 保存 `dead_prev` 再判断 | 阵亡当步 `dead_prev` 是 0，逻辑被污染 → **仍不复活** |
| 用 `DEAD + dt` 反推上一步 | `DEAD` 被 clamp 后反推得 `dt(>0)` → "读条结束"误判为"正在读条"，**每局第一步白送复活**（HP 400→80） |

**正确做法**：在**修改 `DEAD` 之前**取 `was_reviving = DEAD > 0`，然后
`respawning = was_reviving & (DEAD <= 0) & ~just_died`。

**怎么发现的**：规则基线评测给出**荒谬数字** —— "随机"策略胜率 0.99（+74.1），
"规则"策略胜率 0.00（−78.2），而规则策略冒烟测试占点率是 1.000。
**矛盾数字就是 bug 的信号，不能当结论用。**

### 5.2 `step()` 依赖陈旧的 `_vis`

改为在 `step()` 里现算（`_los_blocked()` 无副作用），同时消除了"用上一帧陈旧可见性"的隐患。

### 4.1 未解问题 #4 详情：塑形在 d ≳ 5.9 m 处"推着策略往外走"

**怎么发现的**：跑 `test_shaping.py` 时有 2 项失败，复核后发现是**断言写错**（不是代码 bug），
但错误断言掩盖了一个真实的副作用：

```
F = γΦ(s′) − Φ(s),  Φ = −tanh(d/σ),  γ = 0.99,  σ = 3.0,  一步位移 0.15 m

原地停留：F = (γ−1)Φ(d)         ⇒ 每步 +0.006 ~ +0.010（越远越大）
向外移动：F_out(d) = γΦ(d+0.15) − Φ(d)
          d=0.8 → −0.043     d=3.0 → −0.012
          d=6.0 → +0.006  ← **转正**
```

**机理**：tanh 饱和后 Φ 变化量趋于 0，而 `(γ−1)Φ ≈ −0.01` 的负漂移也不再变小，
于是"往外走一步"的收益盖过了惩罚。这是"有界 Φ + γ<1"的固有性质。

**为什么值得管**：本项目场地 12×8，中心到角落约 7 m ⇒ **该区域可达**；
且与已知现象方向一致 —— `rmul_3v3_env.py` 注释里记录过"策略跑到离中心 5.9~7.2 m"。

**已做的处置**：`test_shaping.py` 的断言按实情修正（只对 d ≤ 3 m 断言"远离为负"，
d=6.0 转正值改为**打印证据**而非断言失败），并在文件头写明复核记录 —— 不掩盖，不静默。
**未做的**：改公式本身（这是设计决定，需要先讨论是"换有界形式"还是"改 σ/γ 关系"）。

**候选方案**（都还没验证，供讨论）：
- (a) 势函数换成在远处仍单调的形式（例如保留 tanh 但把 Φ 平移，使 Φ→0 而不是 →−1）
- (b) 只在 d < 某阈值内施加塑形（⚠️ 硬截断会破坏 policy invariance，需谨慎）
- (c) 维持现状，靠环境的其它项（占点 +0.10/步）把策略拉回来 —— 但需实测确认够不够

⚠️ 与 `AGENTS.md` §3 冲突仲裁一致：**改塑形前必须先跑 `check_shaping_scale.py` +
`test_shaping.py`**，并作废受影响的旧结论（R2d）。

**为什么以前没发现**：查历史日志（全部 0 次回跳）——

| 日志 | 决策数 | 环境数 | 全局回跳 |
|---|---|---|---|
| A2 当时的 3 份 | 2800 / 5600 / 6000 | 1–2 | 0 |
| 2027 整局 | 24000 | 8 | 0（2027 对手只打中央 ⇒ 无人战亡 ⇒ 无局结束） |
| **2026 整局** | 24008 | 8 | **1601** |

⇒ A2 当时的验证**窗口短到从未跨过一局边界**，缺陷是**既有的**，不是新引入的。

**为什么值得修**（不是洁癖）：A2 的交付目标是"**每个决策可复盘**"。
日志里**没有"局"的标记**，`env + frame` 无法唯一确定一条决策在哪个 episode 里；
多局日志既不能忠实回放，也不能按局统计。**A3（CD 曲线）按局聚合时会直接踩到。**

**候选方案**（三选一，倾向 (b)）：
- (a) 日志加 `episode` 字段（由 `run()` 维护每环境的局计数），回读按 `(env, episode)` 判单调 —— 最忠实；
- (b) `run()` 在检测到某环境 `done` 后**停止记录该环境**（"一运行 = 每环境一局"），
  并在 header 写明口径 —— 最小改动，且与 `logged_match.py` 自称的"跑一局"一致；
- (c) 只放宽回读断言（改成"逐环境按 episode 分段单调"），不改日志格式 —— 治标不治本。

⚠️ 无论哪种，都要**同时**改 `run()` 与 `replay()`，且加一条"构造一局提前结束"的回归
（否则又会像这次一样，靠"跑得更久"才发现）。

### 5.3 未解问题 #7 详情：部分 done 时全量 reset（A2.2）✅ 已修

**现象**：A2.1 修好后跑 8 环境 2026 整局，env7 在 139.9 s 提前结束；日志时间单调通过，
但 env0–6 的 `decision_idx` 在 env7 结束时被清零。T10 的对照组日志里，env1 在 t=1.05 s
出现无来由的 `IDLE -> EXECUTING`。

**根因**：`logged_match.drive()` / T7 在 `done.any()` 时调用 `drv.reset()`，而它是全量重置；
`env.auto_reset(done)` 只重置结束的环境，两边不同步。仍在进行的环境会丢：
`DecisionState`（dwell / age / vulnerable_seen）、`SafetyMonitor`（含 `ever_nan` 永久停机）、
`TacticalMachine`（当前任务/超时），以及 `_dec_count`。

**处置**：`TacticalDriver.reset(env_indices=None)`；`drive()` 传入 `done_idx`；T7 同步。
`None` 保持全量语义，T6 仍覆盖整局重置。T10 增加 `decision_idx` 单调断言。

**证据**：`test_tactical_adapter.py` **56/56**。8 环境那份日志产自修复前，正好保留作
问题证据（`runs/logs/match_2026_20261017_155101.jsonl`）；修复后未重跑 8 环境整局
（T10 已精确构造该场景），A3 前如需可再跑一次。

### 5.4 未解问题 #8 详情：旧赛季复活后的"双重保护期"（待裁决）

**事实（代码 + 日志两边都有证据）**：
- 2026 环境：`respawn_secs = 读条 + respawn_invuln(10 s)`（`rmul_3v3_env.py:1004`），
  且免伤判据含 `DEAD > 0`（`:936`）⇒ 对战术层而言，`DEAD` 归零时无敌已经结束。
- 战术层：`RespawnTracker` 在 `DEAD` 归零的边沿进入 `RESPAWNED_PROTECTED`，再倒数
  `cfg.respawn_invuln_s = 10 s` 且一律 `HOLD_CURRENT_ZONE`。
- 2026 8 环境整局：22407 条决策里 **0 条 `RESPAWNED_VULNERABLE`**，
  `HOLD` 于 `RESPAWNED_PROTECTED` 的有 **3486 条（15.6%）**，ALIVE 仅 4445 条（19.8%），
  DEAD 14476 条（64.6%）。复活后原地 10 s（此时环境侧无免伤）与高死亡率方向一致。

**为什么没直接修**：这会改变 2025/2026 的全部行为与基线数字（R2d），且要先回答
"2026 规则里复活后那 10 s 到底是无敌期间不可操作、还是可操作"——手册原文核对前不动。
2027 分支已由 A1.6 绕开（虚弱期间回补给区，不再原地保护）。

**若核实属实，候选处置**：旧赛季也改为"DEAD 归零即按 ALIVE 处理"（或把环境改成
DEAD/INVULN 分离）。两者都会作废旧基线，需单独立项 + 重跑 `test_respawn`。
